# 004 계약을 어긴 모델 응답은 장애로 다룬다

작성 2026-10-06. 원본 팀 규칙에는 없던 분류다. 공개 재현을 실행되는 서비스로 만들면서([platform.md](../platform.md)) 추가했다.

## 문제

모델 서버가 200을 돌려줬는데 본문이 JSON이 아니거나 `status`가 계약에 없는 값이면, 규칙(`fallback.apply`)은 모르는 분류라며 예외를 낸다. 워커가 이 예외로 멈추면 그 작품은 큐에 남아 같은 실패를 반복하고, 다른 작품도 처리되지 않는다.

## 선택지

| 선택지 | 문제 |
|---|---|
| 품질 미달로 본다 | 모델이 결과를 판단한 것이 아닌데 한 단계 낮춰 버린다. 모델 품질 지표가 서버 문제로 오염된다 |
| 즉시 결과 미도달 | 일시적인 응답 깨짐 한 번에 작품을 포기한다 |
| **장애로 보고 같은 단계를 재시도** | 시도 상한(3회) 안에서 회복을 기다리고, 원인은 인프라 실패로 남는다 |

## 결정

워커가 모델 응답을 계약(`contracts/model_response.schema.json`)으로 검증하고, 어기면 `invalid_response`로 분류한다. 규칙은 이것을 장애 분류에 넣어 같은 단계를 다시 시도한다. 시도 기록에는 `invalid_response`가 그대로 남아 일반 장애와 구분된다.

## 검사

`InvalidResponseIsInfra`(tests/test_fallback.py), 장애 주입 시나리오 5(tests/integration).
